# Native 288×216 Display Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shrink the host↔fabric framebuffer contract and the core's scanout from 320×240 to the game's true native 288×216, eliminating the 10:9 nearest-neighbour upscale and the bottom-16-row crop.

**Architecture:** One resolution end to end, with **one geometry root per language domain**: `BLT_FB_WIDTH/HEIGHT` (refmodel header) roots all C code including vector generators; `` `FB_W ``/`` `FB_H `` (each repo's `blitter_defs.vh`) roots all RTL **and testbenches** with qword strides/pixel counts derived by expression, never re-typed; `MISTER_WIDTH/HEIGHT` (Makefile define) roots the host display path. The C↔Verilog and display↔fabric boundaries are enforced mechanically (extended `contract-check` greps + a `static_assert`), so a future resolution change edits exactly three root pairs and the checks catch any straggler. GM is told its window is 288×216 (its real GEN8 size) so its composite quad becomes a 1:1 blit; the video timing becomes 288×216 active with a uniform /9 pixel divider (380 px × 9 = 3420 MCLK/line — H rate and 59.92 Hz unchanged). Spec: `docs/superpowers/specs/2026-07-27-native-288x216-design.md` (mister-gmloader).

**Tech Stack:** C/C++ (refmodel + gmloader host), SystemVerilog (Icarus sim + Quartus 17.0), Docker armhf cross-build, GitHub Actions self-hosted Windows Quartus runner, `deploy.py` over ssh/scp.

## Global Constraints

- New geometry everywhere: **W=288, H=216, FB_QWORDS=15552** (288·216·2/8), **FB_PIXELS=62208**, **row stride 72 qwords / 576 bytes**, **frame 124,416 bytes**.
- **Single-source rule:** width/height literals may appear ONLY at the three roots — `refmodel/blitter_ref.h` (`BLT_FB_WIDTH/HEIGHT`), each repo's `rtl/blitter_defs.vh` (`` `FB_W ``/`` `FB_H ``), and `Makefile.gmloader` (`-DMISTER_WIDTH/HEIGHT`). Every other dimension (qwords, pixels, strides, last-column, control-block bases) is a derived expression or a `localparam` computed from a root. Testbenches and vector generators consume the roots via `` `include ``/`#include` — no hand-mirrored numbers.
- mfgpu sim windowed layout derives from FB size: FB1_QW = FB_QWORDS = 15552, VCTRL_QW = 2·FB_QWORDS = 31104, BLTCTRL_QW = VCTRL+16 = 31120, RING_QW = VCTRL+32 = 31136; `SRC_QW=39000` and `MEM_QW=65536` stay (ring end 31136+1024 < 39000 holds).
- Timing: **H** 288 active + 16 FP + 34 sync + 42 BP = 380 total, uniform /9 (380·9 = 3420 MCLK/line, 15,700 Hz). **V** 216 active + 14 FP + 3 sync + 29 BP = 262 total, 59.92 Hz.
- DDR layout is otherwise untouched: BUF0/BUF1 base addresses, 0x8000-qword buffer spacing, VSYNC/DIAG placement all stay.
- The wire contract carries **no version handshake**: the engine binary and the RBF must always be deployed as a pair (Task 7). Never test a new engine against an old RBF or vice versa.
- **DSP-sizing caution:** the row-stride multiplies in `blitter_top.sv`/`comp_pipeline.sv` are timing-closed 16×16 DSPs. When replacing `16'd80`, bind the derived constant through an explicitly-sized `localparam [15:0]` — do not drop an unsized macro expression into the multiply operand.
- Repos/branches: mfgpu edits go in the `gmloader-next/3rdparty/mfgpu` submodule checkout on its existing branch **`trilist-opcode-10`**; gmloader-next work on branch **`feat/native-288x216`** off `master`; maldita.castilla-mister work on branch **`feat/native-288x216`** off `milestone-a`.
- Order matters: maldita's golden generator (`fpga/sim/gen_tri_golden.mk:36`) reads the refmodel **from the gmloader-next submodule checkout on disk** — Task 1 must be complete before Task 5 regenerates vectors.
- No CI runs any battery; every gate below is a local command. Run host-side commands with `/opt/homebrew/bin` on PATH.
- All host test builds are host-native (bare `c++`/`cc` in the recipes) — no cross toolchain needed until Task 7's engine build.

// With the FB contract at the game's real 288x216, GM's composite quad is a
// straight 1:1 blit: screen=[0,0..288,216], UVs over the used region of the
// padded 512x256 GL page. This case locks that end state: content drawn INTO
// the app surface and then composited to WORK must land pixel-identical to the
// same content drawn directly to WORK. Any residual scale, half-texel phase,
// or dropped/duplicated row/column breaks the quadrant borders.
static int case_appsurf_composite_1to1(void) {
    enum { PAGE_W = 512, PAGE_H = 256 };
    const float UMAX = (float)BW / PAGE_W;        // 288/512
    const float VMAX = (float)BH / PAGE_H;        // 216/256
    const uint32_t APPSURF_FBO = 70, APPSURF_TEX = 71;

    static const uint8_t whitepx[4] = { 255,255,255,255 };
    RTexture white = { whitepx, 1, 1, 1, 1, 0, 1 };

    // Position-keyed content: four solid quadrants with strong distinct colors.
    // Drawn identically into (a) the app surface then composited, (b) WORK direct.
    auto colorquad = [&](float x0,float y0,float x1,float y1,float r,float g,float b, BVtx *q){
        BVtx a[6] = { {x0,y0,0,0,r,g,b,1},{x1,y0,0,0,r,g,b,1},{x1,y1,0,0,r,g,b,1},
                      {x0,y0,0,0,r,g,b,1},{x1,y1,0,0,r,g,b,1},{x0,y1,0,0,r,g,b,1} };
        for (int i=0;i<6;i++) q[i]=a[i];
    };
    const float HX = BW/2.0f, HY = BH/2.0f;
    BVtx q_tl[6], q_tr[6], q_bl[6], q_br[6];
    colorquad(0,0,  HX,HY,  1,0,0, q_tl);   // red
    colorquad(HX,0, BW,HY,  0,1,0, q_tr);   // green
    colorquad(0,HY, HX,BH,  0,0,1, q_bl);   // blue
    colorquad(HX,HY,BW,BH,  1,1,0, q_br);   // yellow

    // (a) draw into the app surface, then composite with the device-geometry quad.
    // GL FBO convention: v is bottom-origin over the padded page (v@top = VMAX).
    static uint8_t  rgba_a[BW*BH*4];
    static uint16_t fb_a[BW*BH];
    RSurface s_appsurf = { nullptr, BW, BH, APPSURF_FBO };
    RSurface s_work_a  = { rgba_a, BW, BH, 0 };
    RasterBackend_MFGPU_SetDefaultSurface(rgba_a);
    RasterBackend_MFGPU_SetAppSurface(APPSURF_FBO, APPSURF_TEX);
    RasterBackend_MFGPU_TestReinit(0);
    backend_mfgpu.frame_begin();
    backend_mfgpu.clear(&s_appsurf, 0, 0, 0, 255);
    backend_mfgpu.draw(&s_appsurf, q_tl, 2, &white, RB_NONE, 0.f, next_key());
    backend_mfgpu.draw(&s_appsurf, q_tr, 2, &white, RB_NONE, 0.f, next_key());
    backend_mfgpu.draw(&s_appsurf, q_bl, 2, &white, RB_NONE, 0.f, next_key());
    backend_mfgpu.draw(&s_appsurf, q_br, 2, &white, RB_NONE, 0.f, next_key());
    RTexture apptex = { nullptr, PAGE_W, PAGE_H, 1, 1, 0, 1 };
    apptex.gl_name = APPSURF_TEX;   // sample the app-surface page (mirrors vflip case)
    BVtx comp[6] = {
        { 0,      0,      0.f,  VMAX, 1,1,1,1 }, { (float)BW, 0,      UMAX, VMAX, 1,1,1,1 },
        { (float)BW, (float)BH, UMAX, 0.f, 1,1,1,1 },
        { 0,      0,      0.f,  VMAX, 1,1,1,1 }, { (float)BW, (float)BH, UMAX, 0.f, 1,1,1,1 },
        { 0,      (float)BH, 0.f,  0.f, 1,1,1,1 },
    };
    backend_mfgpu.draw(&s_work_a, comp, 2, &apptex, RB_NONE, 0.f, next_key());
    backend_mfgpu.frame_end();
    RasterBackend_MFGPU_TestCopyFB565(BW, BH, fb_a);

    // (b) same quadrants drawn straight to WORK — the oracle.
    static uint8_t  rgba_b[BW*BH*4];
    static uint16_t fb_b[BW*BH];
    RSurface s_work_b = { rgba_b, BW, BH, 0 };
    RasterBackend_MFGPU_SetDefaultSurface(rgba_b);
    RasterBackend_MFGPU_SetAppSurface(0, 0);
    RasterBackend_MFGPU_TestReinit(0);
    backend_mfgpu.frame_begin();
    backend_mfgpu.clear(&s_work_b, 0, 0, 0, 255);
    backend_mfgpu.draw(&s_work_b, q_tl, 2, &white, RB_NONE, 0.f, next_key());
    backend_mfgpu.draw(&s_work_b, q_tr, 2, &white, RB_NONE, 0.f, next_key());
    backend_mfgpu.draw(&s_work_b, q_bl, 2, &white, RB_NONE, 0.f, next_key());
